# 手動測試與已知問題

自動測試:`dotnet test tests/Time-to-stand-up.Tests`。以下是需要人工確認的部分。

所有手動測試都建議用暫存設定資料夾啟動,不碰真正的 `%AppData%\Time-to-stand-up`(刪掉該資料夾即可重看首次啟動畫面)。帶 `--config-dir` 時不做單一執行個體檢查,可以和已安裝的版本並存:

```bash
dotnet run --project src/Time-to-stand-up.App -- --config-dir C:\temp\standup-test --work 0.5 --break 0.3
```

命令列參數(只影響這次執行,不寫回設定檔):

- `--work <分鐘>`、`--break <分鐘>`:覆寫工作間隔、休息時長,可為小數(`0.5` = 30 秒)。
- `--config-dir <資料夾>`:改用指定資料夾存放 `config.json`。

## 設定檔

`config.json` 欄位:`workMinutes`、`breakMinutes`、`firstRunCompleted`、`theme`(`System` / `Light` / `Dark`)、`smartPause`(預設 true)、`pauseProcesses`(例外程式名稱陣列,預設空)。

- `pauseProcesses` 存正規化後的名稱(小寫、不含路徑與 `.exe`)。不是陣列或含非字串元素:整個欄位回到空清單;個別名稱不合法或超過 50 筆:只丟掉那些名稱;以上都算「欄位被重設」。重複名稱合併,不算重設。

- 預設選項不另存,由數值推導:30/5 = 標準(建議)、60/10 = 較寬鬆、其他 = 自訂。
- 檔案不存在:使用預設值。JSON 損毀:使用預設值,壞檔改名為 `config.json.bak`,啟動時顯示說明。某欄位超出範圍或型別不對:只有該欄位回復預設。未知欄位(包含舊版的 `devMode`、`dev*Seconds`、`idleMinutes`)會被忽略。
- 寫入先寫暫存檔再取代。

## 程式流程

1. **首次啟動畫面**:顯示研究依據與三個預設選項,預選「30 / 5(建議)」。選「自訂」輸入 0、181、abc、3.5 或留空,會即時提示錯誤且「開始使用」變灰。按右上角 X 會結束程式,不寫入設定檔。
2. **開始使用**:系統匣出現橘色「站」圖示並開始計時;`config.json` 內容正確,重新啟動不再出現首次啟動畫面。
3. **設定視窗**:系統匣右鍵 →「設定…」(或左鍵單擊)。有「提醒設定」「例外程式」「研究依據與關於」三個分頁。「儲存」寫入 `config.json`;「回復預設」只改視窗內的值;「取消」不改任何東西。
4. **儲存後立即生效,保留已累計的工作時間**:改成自訂 1 / 1 並儲存,休息會在**啟動後**約 1 分鐘出現。
5. **休息開始時設定視窗自動關閉**,未儲存的修改被丟棄。休息期間系統匣的「立即休息」「設定…」「結束」都是灰的,解鎖後恢復。
6. **休息畫面**:每個螢幕都被蓋住,沙漏倒數,結束後出現「解鎖」按鈕。
7. **智慧暫停**:鎖定(Win+L)或睡眠期間工作計時暫停;離開時間達到休息時長,回來時系統匣跳出「已當作休息,重新開始計時」。**不偵測鍵盤滑鼠閒置**:長時間不動(例如看影片)計時照常,時間到仍會鎖定,需自行按「解鎖」。
8. **單一執行個體**:不帶 `--config-dir` 連續啟動兩次,第二次只顯示「Time-to-stand-up 已經在執行中」,系統匣只有一個圖示。
9. **例外程式**(建議 `--work 0.5 --break 0.3`):
   - 「例外程式」分頁輸入 `notepad` 按 Enter(不會觸發儲存),按「儲存」。開啟記事本並最小化,等超過 30 秒:不出現休息前提示與休息畫面;滑鼠停在系統匣圖示顯示「暫停中:notepad」。
   - 關閉記事本:約 30 秒後才出現休息(從關閉時重新計時)。
   - 輸入 `C:\x\Foo.EXE` 存為 `foo`;重複加入顯示「已在清單中」;輸入 `a|b` 顯示錯誤;選取項目按 Delete 或「刪除」可移除。
   - 「從執行中的程式挑選…」只列出有視窗的程式,可 Ctrl 多選;已在清單中的項目標示「已在清單中」且不會重複加入。
   - 休息畫面期間開啟例外程式不影響倒數;解鎖後若程式仍開著,立即暫停。
   - 深色 / 淺色主題下清單外觀正常;清單為空時工作管理員的 CPU 與先前無差異(不列舉行程)。
10. **開機自動啟動核取方塊**:勾選 / 取消並儲存後,`HKCU\Software\Microsoft\Windows\CurrentVersion\Run` 的 `Time-to-stand-up` 值跟著出現 / 消失。注意:用 `dotnet run` 勾選時,寫入的是當下 bin 資料夾的 exe 路徑。

## 安裝程式

在乾淨環境(另一個 Windows 帳號或 VM,最好沒裝 .NET)驗證:

1. 執行 `dist\Time-to-stand-up-Setup-<版本>.exe`:不跳出系統管理員權限要求;附加工作「開機時自動啟動」預設勾選、「建立桌面捷徑」預設不勾。
2. 完成後程式啟動、出現首次啟動畫面;開始功能表有「Time-to-stand-up」。
3. Run 鍵有 `Time-to-stand-up`,值為 `"%LocalAppData%\Programs\Time-to-stand-up\Time-to-stand-up.exe"`;**登出再登入**後程式自動出現在系統匣。
4. 程式執行中再跑一次安裝檔(升級):舊程式被自動結束、安裝成功、設定保留。
5. 安裝時取消「開機時自動啟動」:Run 值被移除。
6. 解除安裝:程式資料夾、捷徑、Run 值都被移除;詢問是否刪除設定檔,選「否」時 `%AppData%\Time-to-stand-up` 仍在。

## 已知問題與限制

- **沒有保護機制**:使用者可以把工作間隔改成 180 分鐘,或在系統匣直接「結束」(見 [ROADMAP](ROADMAP.md))。無法防止用工作管理員結束程式;本工具的目標是「增加阻力」,不是強力防護。不干擾 Ctrl+Alt+Del 與系統鎖定畫面。
- **命令列覆寫期間開設定視窗**:視窗顯示設定檔的值,不是覆寫值;按「儲存」後,存下的值會取代這次執行的覆寫。
- **安裝檔沒有程式碼簽章**:下載者會看到 SmartScreen 警告。
- **多螢幕混合 DPI**(例如一個 100%、一個 150%)尚未實測。已在 2 個 2560×1440 螢幕上確認都被蓋住。
- 「系統關閉動畫」時沙漏改為每秒更新的靜態模式,沒有實機驗證。
- 時間以系統時鐘計算;系統時間被往回調時,經過時間不會變成負值,但倒數會暫停到時鐘追回。
- 資源用量(M1 量測,Release、2 個 2560×1440 螢幕):工作狀態約 56 MB、CPU 約 0.2%;休息動畫期間約 156 MB、CPU 約 5%(單核)。之後沒有重新量測。
- 工具無法驗證使用者是否真的站起來走動。
- **例外程式只比對行程名稱**:不看路徑,同名的不同程式會被視為同一個;每 2 秒列舉一次,所以程式關閉後最多約 2 秒才恢復計時。把常駐程式(例如 `explorer`)加入清單就永遠不會提醒,這是刻意不做保護(同「沒有保護機制」)。

## 研究引用的查證紀錄

- App 內顯示「Duran 等人,2023(最後作者為 Diaz)」:PubMed 記載該篇(PMID 36728338)第一作者是 Duran AT。文字集中在 `src/Time-to-stand-up.Core/Content/HealthCopy.cs`。
- 只放摘要查得到的數字:Duran 2023——11 位受試者、連續坐 8 小時、5 種安排、只有每 30 分鐘走 5 分鐘使血糖反應顯著降低、所有走動安排收縮壓都較低(降幅最大為每 60 分鐘走 1 分鐘 5.2 mmHg、每 30 分鐘走 5 分鐘 4.3 mmHg)。
- **不使用**(摘要查不到或過時):「血糖降 58%」、「血壓降 4–5 mmHg 相當於 6 個月運動」、「疲勞與情緒改善」、「唯一同時降血糖與血壓」、Diaz 2017 的「連續坐超過 30–60 分鐘」門檻、WHO 2002 年「全球 60–85% 久坐、每年 200 萬人死亡」。
- Diaz 2017(PMID 28892811)只放 7,985 人、追蹤中位數 4 年與「兩項久坐指標各自都與全因死亡風險有關」。Dunstan 2012(PMID 22374636)的數字(19 位、45–65 歲、每 20 分鐘走 2 分鐘、血糖與胰島素較低)與摘要一致。
- 前兩份研究是小樣本、短期、受控環境實驗;Diaz 2017 是觀察性研究,只能看出關聯。本工具不是醫療建議。
