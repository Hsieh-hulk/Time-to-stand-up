# StandUp 站起來

Windows 上的強制休息提醒工具:連續工作到設定時間後,以全螢幕置頂畫面強制休息,倒數結束後按下解鎖才能繼續。規格見 [SPEC.md](SPEC.md)。

**目前進度:M2**(M1 的計時器、休息狀態機、全螢幕多螢幕覆蓋、沙漏動畫、解鎖按鈕,加上設定檔、設定視窗、首次啟動畫面、研究依據與關於頁)。閒置偵測(M3)、程式排除清單(M4)、跳過機制(M5)、完整系統匣與打包(M6)尚未實作。

## 執行

需要 .NET SDK(本專案以 `net8.0` 為目標,已用 SDK 10 驗證可建置)。

```bash
dotnet run --project src/StandUp.App
```

第一次執行會先出現「首次啟動畫面」(研究依據、預設選項、「開始使用」);按下後才開始計時,並寫入 `%AppData%\StandUp\config.json`,之後不再出現。

命令列參數(測試用):

- `--work <分鐘>`:**覆寫**設定檔的工作間隔,只影響這次執行,不寫回檔案。可為小數。
- `--break <分鐘>`:**覆寫**設定檔的休息時長,同上(例如 `0.5` = 30 秒)。
- `--config-dir <資料夾>`:改用指定資料夾存放 `config.json`,不碰真正的 `%AppData%\StandUp`(自動化驗證用)。

```bash
dotnet run --project src/StandUp.App -- --work 1 --break 0.5
```

執行單元測試:

```bash
dotnet test tests/StandUp.Tests
```

## 設定檔

`%AppData%\StandUp\config.json`:

```json
{
  "workMinutes": 30,
  "breakMinutes": 5,
  "firstRunCompleted": true
}
```

- 預設選項不另存,由數值推導:30/5 = 標準(建議)、60/10 = 較寬鬆、其他 = 自訂。
- 工作間隔 1–180 分鐘、休息時長 1–30 分鐘,只接受整數。
- 檔案不存在:使用預設值。JSON 損毀:使用預設值,壞檔改名為 `config.json.bak`(不會被悄悄蓋掉),啟動時會顯示一則說明。某個欄位超出範圍或型別不對:只有該欄位回復預設,其他欄位保留。未知欄位會被忽略。
- 寫入先寫暫存檔再取代。

## M2 手動測試步驟

先用不碰真實設定的方式啟動:`dotnet run --project src/StandUp.App -- --config-dir C:\temp\standup-test`(之後想重看首次啟動畫面,刪掉該資料夾即可)。

1. **首次啟動畫面**:出現研究依據(Duran 等人 2023、Dunstan 等人 2012、Diaz 等人 2017)與三個預設選項,預選「30 / 5(建議)」。選「自訂」,輸入 0、181、abc、3.5 或留空,會即時出現錯誤提示且「開始使用」變灰;輸入 1~180 / 1~30 的整數才可按。直接按視窗右上角 X 會結束程式,不寫入設定檔。
2. **開始使用**:選好後按「開始使用」,系統匣出現橘色「站」圖示並開始計時;檢查資料夾裡的 `config.json` 內容正確,重新啟動不再出現首次啟動畫面。
3. **設定視窗**:系統匣圖示右鍵 →「設定…」。切換選項、自訂輸入,按「儲存」後 `config.json` 更新。「回復預設」會把視窗內選項回到 30/5(按「儲存」才寫入),「取消」不改任何東西。「研究依據與關於」分頁列出三份研究、WHO 2020 指引的一句說明、限制與「本工具不是醫療建議」聲明。
4. **儲存後立即生效,且保留已累計的工作時間**:在「設定…」把間隔改成自訂 1 / 1 並儲存,休息會在**啟動後**約 1 分鐘出現(不是儲存後再 1 分鐘)。反過來,間隔改長則休息延後。
5. **休息開始時設定視窗自動關閉**:打開設定視窗、改一個值但不儲存,等休息開始(可用 `--work 0.5 --break 0.3` 加快);設定視窗會自動消失、修改被丟棄。休息期間系統匣的「立即休息」「設定…」「結束」都是灰的,解鎖後恢復。
6. **命令列覆寫不寫回檔案**:`--work 1 --break 0.5` 啟動並看完一輪流程,`config.json` 的數值不變。

M1 的手動測試(休息畫面、沙漏、多螢幕、解鎖)步驟不變,仍可照舊用 `--work 1 --break 0.5` 驗證。

## 已知問題與限制

- **設定視窗沒有任何保護**:使用者可以自己把工作間隔改成 180 分鐘,或在系統匣直接「結束」。保護機制屬於 SPEC 3.5(跳過機制與密碼,尚未定案),要到 M5 才處理。
- **命令列覆寫期間開設定視窗**:視窗顯示的是設定檔的值,不是覆寫值;按「儲存」後,存下的值會取代這次執行的覆寫。
- **引用的第一作者**:SPEC 寫的「Diaz 等人 2023」,PubMed 記載該篇第一作者是 Duran AT,Diaz KM 是最後作者。App 內顯示為「Duran 等人,2023(最後作者為 Diaz)」,文字集中在 `HealthCopy`,要改回很容易。
- **研究數字只放查證過的**:Duran 2023 摘要(PMID 36728338)查得到的才放——11 位受試者、連續坐 8 小時、5 種安排、只有每 30 分鐘走 5 分鐘使血糖反應顯著降低、所有走動安排收縮壓都較低(降幅最大為每 60 分鐘走 1 分鐘 5.2 mmHg、每 30 分鐘走 5 分鐘 4.3 mmHg)。以下說法在摘要查不到,所以**不使用**:「血糖降 58%」(只見於二手媒體)、「血壓降 4–5 mmHg 相當於 6 個月運動」、「疲勞與情緒改善」、「唯一同時降血糖與血壓」(實際上所有安排的收縮壓都顯著下降)。Diaz 2017(PMID 28892811)只放 7,985 人、追蹤中位數 4 年與「兩項久坐指標各自都與全因死亡風險有關」;「連續坐超過 30–60 分鐘」的門檻摘要裡沒有(摘要的分組切點是平均每段 7.7–12.4 分鐘),因此不寫。WHO「全球 60–85% 久坐、每年 200 萬人死亡」出自 2002 年新聞稿,已過時,不使用。Dunstan 2012(PMID 22374636)的數字(19 位、45–65 歲、每 20 分鐘走 2 分鐘、血糖與胰島素較低)與摘要一致。研究只放文字引用,沒有連結。
- 設定檔損毀時啟動會跳出一個說明對話框(需按「確定」才繼續),這是計畫之外為了不讓壞檔被悄悄蓋掉而加的提示。
- 閒置偵測、鎖定/睡眠處理是 M3:目前工作計時在電腦鎖定或睡眠期間照常累積,喚醒後若已超過工作間隔會立刻進入休息。
- 系統匣目前只有「立即休息」「設定…」「結束」三項,都只在工作狀態可用;「結束」沒有任何驗證。圖示是程式畫的臨時圖示。完整系統匣是 M6。
- 多螢幕:已在 2 個 2560×1440 螢幕上確認兩邊都被蓋住。**混合 DPI(例如一個 100%、一個 150%)尚未實測**,程式有針對 DPI 變更重新套用位置,但沒有實機驗證。設定視窗與首次啟動畫面只在 100% 縮放的主螢幕上看過。
- 「系統關閉動畫」時沙漏改為每秒更新的靜態模式,這條路徑目前沒有實機驗證。
- 時間以系統時鐘計算;系統時間被往回調時,經過時間不會變成負值,但倒數會暫停到時鐘追回。
- 資源用量(M1 時量測,Release、2 個 2560×1440 螢幕):工作狀態約 56 MB、CPU 約 0.2%;休息動畫期間約 156 MB、CPU 約 5%(單核)。M2 沒有重新量測。
- 無法完全防止使用者用工作管理員結束程式;本工具的目標是「增加阻力」,不是強力防護。不干擾 Ctrl+Alt+Del 與系統鎖定畫面。
- 工具無法驗證使用者是否真的站起來走動。
- 提示文字說的是「研究顯示」,不是醫學證實:引用的前兩份研究都是小樣本、短期、受控環境下的實驗,觀察的是走動後短時間內的反應,不能視為長期健康效果的依據;第三份(Diaz 2017)是觀察性研究,只能看出關聯、不能推論因果。本工具不是醫療建議,若有健康疑慮請諮詢醫師。
